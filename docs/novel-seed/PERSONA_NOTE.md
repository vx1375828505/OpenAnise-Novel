# persona.md 集成说明（供 B4 / 应用侧处理）

> 本说明按 B0 决策 **D5**（persona 归属 = 应用内置人格常量，用户不能当普通技能关掉）给出。
> 本文件放在 `out/subagents/` 根目录，**不进 `novel-writing/references/`**，
> persona.md 本身也不进技能系统。

## 一、结论

`persona.md`（PenAi 默认人格卡 / 系统提示词）**不作为技能打包**，应作为**应用内置常量**，
在构造系统提示词时直接拼入。理由：

- 人格卡决定助手的身份、口吻、工具纪律与安全约束，属于「始终生效的底座」，
  而不是「按需读取的资料」；做成技能会被用户在技能面板里关掉，导致人格失效。
- D5 已拍板：应用内置人格常量，不可当普通技能关闭。

## 二、原文路径

- 源文件：`C:\1111\openanise-skills\ref-old\prompts\penai-novel\persona.md`
- 原文自述：该文件是 Anise Write 默认人格卡 `roleSetting` 全文，历史上由
  `NovelPersona.ensureInstalled()` 写入 `filesDir/quro_personas.json`，经
  `QuroSoulPromptEngine` 注入系统提示词。
- 内容结构：`一、能力边界` / `二、工具使用策略` / `三、安全约束` / `四、输出格式约定`。

## 三、建议的集成位置（B4 核对）

- **首选**：`ChatViewModel` 的**系统提示词组装处**注入。方案文档证据 11 指出，
  Anise 侧系统提示词在
  `ChatViewModel.kt:16484-16490`（`skillRepository?.skillPromptFragment(activeSessionId)`）
  附近拼装——人格常量应在这段系统提示词组装逻辑里，作为**基础人格段**先于
  `<available_skills>` 片段拼入，保证每轮都在场。
- **备选**：若应用已有独立的人格卡/系统提示词仓库（旧 `QuroSoulPromptEngine` 对应实现），
  则把 persona.md 全文作为默认 `roleSetting` 常量注册进去，并确保：
  1. 用户不可通过「关闭技能」的方式关闭它（D5 硬约束）；
  2. 若仍允许用户在人格卡页面编辑文案，编辑的是这份常量的副本，而非技能开关。

## 四、移植改写提示（原文含旧工具语义，需 B4 处理）

persona.md 原文写于旧版，其中「二、工具使用策略」表与纪律条款点名了三个旧版写作工具
（写新章 / 续写 / 润色）与旧落盘/备份表述（`.polish-bak`、`overwrite` 参数等）。
这些旧工具在 fix-compile 中已不存在。

B4 将 persona 作为内置常量集成时，建议：

1. 保留「一、能力边界」「三、安全约束（不可逆操作需确认）」「四、输出格式约定」
   中**与工具无关**的普遍条款（简体中文、写完三行内汇报、不替用户做不可逆删除、
   不外传不臆造、不用网络腔等）。
2. 「二、工具使用策略」整节**按新基座实际工具族重写**：用当前可用的写作/章节工具
   替换旧工具名，并保留其纪律内核（先定位再动手、细纲先行、一次一章、失败照实说、
   文风档位）。不要原样注入点名旧工具的文案，否则模型会尝试调用不存在的工具。
3. 保留「你是 Anise Write ……签约编辑兼代笔搭档」的人格基调与身份陈述。
