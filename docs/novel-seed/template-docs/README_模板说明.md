# 小说项目库 · 空模板（底子 v1）

> 这是从一套跑了 104 章、经多次重构验证过的写作库抽象出来的**空模板**。
> 用途：① 开新书时复制它当骨架；② 将来作为 App「一键开新书」自动生成的蓝本。
> 权威原件在 `C:\222\小说项目`（只读，本模板不改动它）。

## 一、这套库为什么能撑几千章（设计原理）

1. **一千章不靠脑子记** — 每章一个文件 `第NNN章：标题.txt`，补零排序；剧情现在时、人物状态单独放，不混进进度。
2. **一个事实只有一个家** — `055_约束.md` 的"唯一事实源"表规定每个事实的权威位置，别处只引用不复制。这解决长篇的头号死法：同一设定散落十处、改一处漏九处。
3. **文件卡 + 门牌 + 连续编号** — 每个文件开头写"作用/何时用/上游/下游"，每个文件夹一个 `000__子路由.md` 门牌，活跃文件全局连续编号。换会话/换平台/换 AI，读两页就能接上。
4. **库自己会维护** — 变更日志、体检、度量、退役归档。作废文件不删，加 `_废弃_` 前缀归档，所以反复重构也不丢历史。
5. **质量闸门** — 一轮只执行一份规则；动手前先出方案；没拍板全是草稿。

## 三、开工与干活流程（写进 001_总路由 的铁律）

1. 开工只读两样：`001_总路由.md`（去哪找）+ `006_进度.md`（写到哪）。
2. 精修/改稿/检查：查 `061_规则调用路由.md`，按本轮唯一主问题选**一份**专项规则（062—083），一轮一份。
3. 写新章：走 `012_场景卡_写新章.md`。
4. 动手前复述任务 + 出方案，**等用户拍板**；没拍板 = 草稿，不动正文。
5. 交付两件套：优化后稿页 + 对照页（`make_diff.py`）。写新章四件：稿子/对照页/P3数值/改动清单。
6. 改完三同步：目录 + 进度 + 相关文件卡；改完 `rg` 扫旧串确认零残留。
